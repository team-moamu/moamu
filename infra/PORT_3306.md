# macOS 3306 포트 확보

먼저 3306에서 요청을 받는 프로세스를 확인합니다. `sudo`가 요구하는 암호는 Mac 로그인 암호이며 입력할 때 화면에 표시되지 않습니다.

```sh
sudo lsof -nP -iTCP:3306 -sTCP:LISTEN
```

출력의 `COMMAND`, `PID`, `USER`를 확인합니다. 아무것도 출력되지 않으면 바로 README의 실행 단계로 넘어갑니다. 아래 `12345`는 예시이므로 **조회한 실제 PID로 바꿔서** 프로세스 경로와 시작 시각을 확인합니다.

```sh
ps -p 12345 -o pid,ppid,user,lstart,comm
```

### 서비스로 실행 중인 MySQL 종료

Homebrew로 설치한 MySQL이라면 서비스 이름을 확인한 뒤 해당 서비스만 종료합니다. 서비스 종료는 자동 재시작 등록도 해제합니다. `Name`이 `mysql`인 경우:

```sh
brew services list
brew services stop mysql
```

`Name`이 `mysql@8.4`라면 마지막 명령을 `brew services stop mysql@8.4`로 바꿉니다. 관리자 계정으로 등록된 서비스는 `sudo brew services list`에서 확인하고, 해당 서비스 이름으로 `sudo brew services stop mysql` 등을 사용합니다.

MySQL 공식 설치 프로그램으로 설치했다면 시스템 설정의 MySQL 항목에서 `Stop MySQL Server`를 선택합니다. 자동 시작 옵션도 해제하면 재부팅 후 같은 포트 충돌을 피할 수 있습니다.

Docker가 포트를 쓰고 있다면 실행 중인 컨테이너를 확인합니다.

```sh
docker ps --format 'table {{.ID}}\t{{.Names}}\t{{.Ports}}'
```

`PORTS`에 `127.0.0.1:3306->...` 또는 `0.0.0.0:3306->...` 등 **왼쪽 호스트 포트가 3306**인 컨테이너를 찾아 아래 `컨테이너_ID`를 실제 ID로 바꿔 종료합니다. `3306/tcp`만 표시된 것은 호스트 포트 점유를 뜻하지 않습니다.

```sh
docker stop 컨테이너_ID
```

`com.docker.backend` 전체를 종료하면 다른 컨테이너도 함께 중단될 수 있으므로 해당 컨테이너만 종료합니다.

### 일반 프로세스 종료와 강제 종료

종료할 대상으로 확인한 프로세스에 먼저 정상 종료 신호를 보냅니다. 아래 `12345`도 실제 PID로 바꿉니다.

```sh
sudo kill -TERM 12345
```

잠시 후 다시 조회합니다.

```sh
sudo lsof -nP -iTCP:3306 -sTCP:LISTEN
ps -p 12345 -o pid,ppid,user,lstart,comm
```

**동일 PID·시작 시각·프로세스가 계속 포트를 사용하고 정상 종료되지 않을 때만** 강제 종료합니다. 강제 종료는 진행 중인 DB 작업을 끊고 복구 작업을 유발할 수 있습니다.

```sh
sudo kill -9 12345
```

PID가 바뀌어 다시 실행됐다면 강제 종료를 반복하지 말고, 위의 서비스 종료 방법으로 자동 재시작을 중지합니다. 포트가 비었는지 마지막으로 확인합니다.

```sh
sudo lsof -nP -iTCP:3306 -sTCP:LISTEN
```

출력이 없으면 다음 단계로 진행합니다. 이 안내는 기존 DB 데이터 파일을 삭제하지 않습니다.
